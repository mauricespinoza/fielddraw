Export the map view

What is on screen right now, framed the way a figure in a report is framed: a zebra border with latitudes and longitudes, a graphic scale bar and a north arrow.

The map itself is an image in all three — it is drawn by the graphics card and there are no vectors to recover from it. Everything around it (frame, labels, scale bar, north) is vector in the SVG and the PDF, so the lettering can be restyled in Illustrator or Inkscape without exporting again. The sheet is always taken in plan view: tilted or with 3D terrain on there is no single scale and no honest coordinate frame.

Working scale

Locked, the map pans but does not zoom, and the scale is held as you move north or south — the denominator drifts with latitude on its own. Pinch zoom and two-finger rotate are off while it lasts.

This screen

The browser reports the resolution but not how big the glass is, so the diagonal is the one thing that has to be told. 0.28 mm is the OGC standard pixel — the assumption QGIS and ArcGIS make — so leaving it there keeps a 1:25 000 here identical to theirs, comparable between tools but not measurable with a ruler. Setting the real size of this screen does the opposite: the map measures what it says, and stops matching QGIS. Pick whichever matters for the job.

The surest way, and the only one that does not take the declared diagonal on trust: hold a ruler against the bar and type what it really measures. The bar is as wide as this panel allows, so a millimetre misread is well under one percent.

Elevation model

.pmtiles with Terrain-RGB tiles, the lightest way to carry a DEM into the field: one file, read by ranges, already pyramided, and its tiles are decoded by the same code as the AWS model. .mbtiles works too, but it is SQLite and loads whole into memory.

A tile file says nothing about whether it holds an image or metres, so which button you press is the answer. Once loaded it becomes the elevation source for profiles, plane fits, thickness, projected traces, hillshade and 3D relief. Only the contour lines keep using the AWS model.

    Symbol size

    Brings the structures, lines and polygons into the drawing, reading their StraboSpot symbology on the way in: a reverse fault arrives as a thrust with its teeth, trace quality becomes the certainty pattern, and geologic-unit tags become map units. Adopted features are drawn in one colour — set it in Symbols — so they stay apart from what you mapped here. Samples and notes stay in their layer.

    Upload always creates a new dataset in the selected project. StraboSpot replaces every spot in a dataset on upload, so existing ones are never written to. Measurements go up as planar orientations, lines as traces and polygons as surface features, so StraboSpot symbolises them on its own.

    A polygon carries no unit name of its own in StraboSpot: the name and the colour come from a project tag. Writing them updates the project itself — existing units keep their own colour and description and only gain the new polygons.

    Line symbology

    Colour and width for every line type — contacts included — plus size, spacing and position where the type carries an ornament. Width is a factor on the type's nominal thickness, so it holds at any zoom. The colour swatch repaints both the trace and its ornament. Position is the perpendicular distance to the trace: the sign picks the side, and flip in the properties menu mirrors the symbol across the trace on one feature, sending it to the other block. Fold arrows straddle the axis, so they have no side to flip.

      Imported from StraboSpot

      Features adopted from a StraboSpot dataset are drawn in a single colour, whatever their type, so a glance tells you which traces you walked and which you inherited. The ornaments and the certainty pattern stay: a thrust still has its teeth. Turn it off and they are drawn with the normal symbology, like anything else in the drawing.

      Strike and dip symbols

      The strike bar is drawn along the measured strike and the tick points down-dip (right-hand rule), so the symbol reads the same here, in QGIS and in StraboSpot. Below 3° the horizontal symbol is used and the tick disappears: a dip that small cannot state a direction. Above 87° the vertical one, with a tick on both sides.

      Layers

      The drawing comes apart into its three pieces — units, traces and measurements — so you can put the contacts against the imagery without the unit fills on top, or clear a crowded outcrop of its dip symbols. They always paint in that order (units underneath, measurements on top), which is why they carry no arrows; everything else is listed top to bottom exactly as it is drawn.
